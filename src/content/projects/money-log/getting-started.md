# MoneyLog 프로젝트 기획과 구현 로드맵

![MoneyLog 대시보드 화면](moneylog.png)

## 1. 개요

**Money Log**는 개인의 수입과 지출을 기록하고, 거래 내역과 소비 패턴을 시각적으로 확인할 수 있는 개인 지출 관리 서비스이다.

사용자는 날짜별로 수입·지출을 등록하고 전체 거래 내역을 확인할 수 있으며, 카테고리별 소비 비율과 월별 소비 흐름을 차트로 확인할 수 있다.

단순한 거래 기록 기능에 그치지 않고, 실제 저장소와 API를 기반으로 데이터를 관리하며 향후 검색·필터·위치 정보·날씨 데이터 등 다양한 외부 데이터를 결합할 수 있도록 확장 가능한 구조로 구성한다.

---

## 2. 주요 기능

### 수입·지출 등록

사용자는 날짜별로 수입과 지출을 등록할 수 있다.

- 수입 / 지출 구분
- 금액
- 카테고리
- 날짜
- 메모

등록된 거래 내역은 저장소에 저장되며 이후 수정 및 삭제가 가능하다.

### 거래 내역 조회

등록된 전체 수입·지출 내역을 조회할 수 있다.

- 날짜
- 거래 유형
- 카테고리
- 금액
- 메모

최근 거래 내역은 메인 화면에서도 확인할 수 있도록 구성한다.

### 카테고리별 소비 비율

등록된 지출 데이터를 카테고리별로 집계해 소비 비율을 시각적으로 제공한다.

```text
식비      35%
쇼핑      25%
교통      15%
카페      12%
기타      13%
```

차트를 통해 사용자가 어떤 영역에 가장 많은 비용을 사용하고 있는지 쉽게 확인할 수 있도록 한다.

### 날씨 정보

현재 위치 또는 설정된 지역의 날씨 정보를 확인할 수 있다.

```text
서울

24°C
맑음
```

향후 소비 데이터와 결합할 수 있도록 확장 가능하게 구성한다.

| 소비 위치 지도 | Map API | 저장된 장소 데이터를 지도 위에 표시 |
| 필터 상태 관리 | Zustand | 복잡한 검색·필터 상태가 필요한 경우 사용 |

## 5. 구현 목표

### 1단계 — 기본 데이터 구조 및 화면 구현

초기에는 별도의 서버 연결 없이 **Mock 데이터**를 사용해 거래 데이터 구조와 화면 구성을 먼저 구현한다.

```text
Mock 데이터
↓
map()
↓
거래 내역 출력
```

핵심 구현 범위는 다음과 같다.

- `Transaction` 타입 정의
- Mock 거래 데이터 구성
- `map()`을 활용한 거래 목록 출력
- 수입 / 지출 UI 구분
- 기본 대시보드 화면 구성
- Empty UI 구성

기본 `Transaction` 데이터 구조는 다음과 같이 구성한다.

```ts
type Transaction = {
  id: string;
  type: 'income' | 'expense';
  amount: number;
  category: string;
  date: string;
  memo?: string;
};
```

### 2단계 — 실제 API 연결 및 상태 관리

실제 API와 연결해 거래 데이터를 조회하고 화면에 표시한다.

```text
API
↓
fetch
↓
useEffect
↓
useState
↓
화면 출력
```

핵심 구현 범위는 다음과 같다.

- `fetch`를 이용한 API 요청
- `async / await` 기반 비동기 처리
- `useEffect`를 이용한 데이터 요청 시점 관리
- `useState`를 이용한 데이터 저장
- Loading / Error 상태 처리
- 거래 데이터 GET 요청
- 등록 / 수정 / 삭제 API 연결
- Supabase를 이용한 실제 데이터 저장

이 단계에서는 직접 API 요청 흐름을 구성하고, 서버에서 받아온 데이터를 화면 상태와 연결한다.

### 3단계 — TanStack Query 기반 서버 상태 관리

기존의 `fetch + useEffect + useState` 구조를 TanStack Query 기반으로 변경한다.

```text
API
↓
TanStack Query
↓
Query / Mutation
↓
화면
```

핵심 구현 범위는 다음과 같다.

- `useQuery`를 이용한 거래 데이터 조회
- `useMutation`을 이용한 등록 / 수정 / 삭제
- 서버 데이터 캐싱
- Loading / Error 상태 관리
- Mutation 이후 거래 목록 갱신
- Query Key를 이용한 서버 상태 구분

기존 방식과 변경 후 구조를 비교하면 다음과 같다.

```text
기존 방식

fetch
+ useEffect
+ useState
```

```text
변경 후

TanStack Query
```

이후 저장된 거래 데이터를 기반으로 통계와 시각화 기능을 확장한다.

```text
거래 데이터
↓
filter / reduce / sort
↓
통계 데이터 생성
↓
차트 데이터 변환
↓
화면 출력
```

핵심 확장 범위는 다음과 같다.

- 카테고리별 지출 합산
- 카테고리별 소비 비율
- 월별 수입·지출 데이터
- 소비 데이터 차트
- 날씨 API 연동
- 대시보드 형태의 데이터 구성

## 6. 추후 확장 기능

### 날짜 및 조건별 검색·필터

거래 내역이 많아졌을 때 원하는 데이터를 빠르게 찾을 수 있도록 검색과 필터 기능을 추가한다.

```text
기간별 조회
카테고리별 조회
수입 / 지출 구분
검색어
금액 범위
```

초기에는 React 상태와 JavaScript의 `filter()`를 활용하고, 필터 조건이 여러 컴포넌트나 화면에서 공유될 정도로 복잡해질 경우 Zustand를 적용한다.

### 소비 통계 Insight

단순히 차트만 제공하는 것이 아니라 저장된 데이터를 기준으로 소비 패턴을 분석해 사용자에게 간단한 Insight를 제공한다.

```text
이번 달 카페 지출이 지난달보다 18% 증가했어요.

이번 달 가장 많은 지출 카테고리는 식비예요.

지난달보다 총 지출이 120,000원 감소했어요.
```

월별 비교, 카테고리별 증감률, 평균 소비 금액 등을 기반으로 구성할 수 있다.

### 날씨 데이터 기반 통계

거래 데이터와 날씨 데이터를 연결해 특정 날씨 조건에서의 소비 패턴을 확인할 수 있도록 확장한다.

```text
비 오는 날 배달 지출

맑은 날 카페 이용 횟수

기온별 외식 지출

날씨별 평균 소비 금액
```

날짜별 날씨 데이터와 거래 내역을 연결해 추가적인 통계 데이터를 제공한다.

### 장소 기반 소비 관리

거래 등록 시 사용 장소를 함께 저장할 수 있도록 기능을 확장한다.

```ts
location: {
  name: string;
  address: string;
  latitude: number;
  longitude: number;
}
```

장소 검색 API를 통해 장소명, 주소, 위도, 경도 정보를 가져오고 거래 데이터와 함께 저장한다.

이후 저장된 위치 데이터를 활용해 소비 장소를 지도에 표시할 수 있다.

```text
자주 방문한 장소

지역별 소비 금액

장소별 누적 지출

소비 장소 지도
```

## Money Log 핵심 방향

Money Log는 사용자의 거래 데이터를 중심으로 다음 흐름이 자연스럽게 연결되도록 구성한다.

```text
기록
↓
저장
↓
조회
↓
가공
↓
분석
↓
시각화
```

초기 버전에서는 수입·지출 관리와 기본 통계에 집중하고, 이후 검색·필터·위치·날씨 데이터를 단계적으로 결합해 개인 소비 데이터를 다양한 관점에서 확인할 수 있는 서비스로 확장한다.
