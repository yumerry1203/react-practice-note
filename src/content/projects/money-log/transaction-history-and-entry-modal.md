# 1-2. 거래내역 서브페이지와 지출 등록 모달 기획

MoneyLog에서 수입과 지출 데이터를 조회하고 새 거래를 등록하는 두 화면의 시안을 정리했다. 거래 내역을 빠르게 찾고, 필요한 입력값을 빠짐없이 등록할 수 있는 흐름을 목표로 한다.

## 1. 거래 내역 화면


![MoneyLog 거래 내역 서브페이지](moneylog-transaction-history.png)

거래 내역 페이지는 상단 요약 정보, 필터, 목록 테이블 순서로 구성했다.

### 화면 구성

1. **상단 네비게이션**
   - 대시보드, 거래 내역, 지출 등록 메뉴 (Header)

2. **요약 카드**
   - 총 거래 수, 총 수입, 총 지출
   - 각 카드에는 이전 달과 비교한 변화 정보를 함께 표시

3. **검색과 필터 영역**
   - 거래명 또는 메모 검색
   - 전체, 수입, 지출 유형 필터
   - 카테고리 선택
   - 조회 기간 선택
   - 최신순 정렬과 초기화 버튼

4. **거래 목록 테이블**
   - 날짜, 유형, 카테고리, 내용, 금액, 메모, 관리 항목
   - 각 행에서 수정과 삭제 기능
   - 목록 하단에는 페이지네이션과 페이지당 노출 개수

### 구현 방향

거래 데이터는 `Transaction` 타입을 기준으로 목록을 렌더링한다. 검색어, 거래 유형, 카테고리, 기간, 정렬 기준은 각각 상태로 관리하고, 선택한 조건을 기준으로 `filter()`와 `sort()`를 적용한 결과를 테이블에 출력한다.

초기 단계에서는 Mock 데이터를 사용해 화면과 필터 흐름을 먼저 만들고, 이후 실제 저장소와 연결할 때는 조회 조건을 API 요청 값으로 전달하고, 등록·수정·삭제 이후 목록이 최신 상태로 갱신되도록 구성한다.

## 2. 지출 등록 모달

### 거래 등록 모달 시안

![MoneyLog 거래 등록 모달](moneylog-transaction-modal.png)

헤더에서 거래 등록 클릭 시 모달에서 사용자가 거래를 입력한 뒤 등록할 수 있다.

### 입력 항목

- **거래 유형**: 지출 또는 수입
- **거래 날짜**: 거래가 발생한 날짜
- **카테고리**: 거래 유형에 맞는 카테고리 선택
- **금액**: 원 단위 금액 입력
- **거래처 / 제목**: 거래 내용을 식별하는 필수 입력값
- **메모**: 선택 입력값
- **다음에도 이 내용으로 계속 등록하기**: 반복 입력을 위한 선택 항목

모달 하단에는 취소와 등록하기 버튼을 배치한다. 닫기 버튼, 취소 버튼, 모달 바깥 영역 클릭, `ESC` 키 동작을 같은 닫기 흐름으로 연결할 수 있다.

### 구현 방향

폼 상태는 각 입력값을 하나의 객체로 관리한다. 거래 유형이 바뀌면 카테고리 선택 항목도 해당 유형에 맞게 바꾸고, 필수값인 유형, 날짜, 카테고리, 금액, 거래처 또는 제목이 비어 있으면 등록하지 않도록 검증한다.

등록이 완료되면 새 거래를 목록 데이터에 추가하고 모달을 닫는다. 등록 성공 후에는 필터 조건을 유지한 상태에서 목록과 상단 요약 카드가 함께 갱신되도록 구성한다.

## 3. 작업 순서

1. `Transaction` 타입과 Mock 거래 데이터를 정의한다.
2. 거래 내역 테이블과 요약 카드를 만든다.
3. 검색, 유형, 카테고리, 기간, 정렬 필터를 연결한다.
4. 거래 등록 모달과 입력 폼을 구현한다.
5. 등록한 거래가 목록과 요약 정보에 반영되도록 연결한다.
6. 이후 수정, 삭제, 페이지네이션, 실제 데이터 저장 기능을 추가한다.

## 정리

- 거래 내역 화면은 요약, 필터, 테이블 순서로 정보를 제공한다.
- 거래 등록은 목록을 유지한 채 모달에서 처리한다.
- 초기에는 Mock 데이터와 화면 흐름을 먼저 만들고, 이후 실제 저장소와 연결한다.
- 등록 후 목록과 요약 카드가 함께 갱신되는 흐름을 목표로 한다.
