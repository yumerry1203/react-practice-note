# 27년 10월 첫째 주 프론트엔드 이슈

최근 프론트엔드와 AI 개발 도구에서 눈에 띈 보안, 스타일링, 브라우저 검증, 프로젝트 Context 관련 내용을 정리

## 1. Next.js 보안 업데이트

Next.js에서 보안 업데이트가 진행되었다. 최근 프론트엔드 프레임워크도 서버 기능과 결합되는 경우가 많아지면서, 단순한 UI 개발뿐 아니라 프레임워크 버전과 보안 업데이트를 꾸준히 확인하는 일이 중요해지고 있다.

Next.js를 사용한다면 의존성 버전을 오래 방치하지 않고, 공식 보안 공지를 주기적으로 확인하는 습관이 필요하다.

## 2. GitHub의 CSS Modules 전환

GitHub는 기존 CSS-in-JS 기반 스타일링을 줄이고 CSS Modules 중심으로 전환했다. 주요 이유는 런타임 비용과 렌더링 성능 개선이었다.

최근에는 CSS-in-JS처럼 JavaScript 런타임에 의존하는 방식보다 CSS Modules, Tailwind CSS, CSS Variables처럼 빌드 타임이나 네이티브 CSS를 적극 활용하는 방식이 다시 주목받고 있다.

스타일링 방식도 개발 편의성뿐 아니라 성능과 유지보수 비용까지 고려해야 한다는 점이 인상적이었다.

## 3. AI Agent와 Chrome DevTools

최근에는 AI가 단순히 코드를 작성하는 것을 넘어 실제 브라우저를 열고 DevTools를 확인하면서 문제를 찾는 방식이 사용되고 있다.

AI Agent는 브라우저를 실행한 뒤 다음과 같은 작업을 수행할 수 있다.

- 화면과 인터랙션 확인
- Console Error와 Warning 확인
- Network 요청 확인
- 문제 코드 수정
- 수정 후 브라우저에서 다시 검증

기존의 **질문 → 코드 생성** 방식에서 점점 **구현 → 실행 → 검증 → 수정**까지 AI가 참여하는 방향으로 발전하고 있다는 점이 흥미로웠다.

Codex에서도 Browser와 Developer mode를 활용해 비슷한 방식으로 프로젝트를 점검할 수 있다. 더 정교한 자동화가 필요하면 Playwright나 Chrome DevTools MCP를 연결할 수 있다.

## 4. AI Agent와 Context의 중요성

최근 AI 개발 도구에서는 모델 자체의 성능만큼 프로젝트에 어떤 Context를 제공하는지가 중요해지고 있다.

프로젝트 구조, 개발 규칙, 공식 문서, 디자인 시스템 등의 정보를 AI에게 충분히 제공하면 같은 모델이라도 결과 품질이 크게 달라질 수 있다.

앞으로는 단순히 AI에게 코드를 작성하게 하는 것보다, AI가 프로젝트를 제대로 이해하고 작업할 수 있도록 환경과 규칙을 만드는 능력도 중요해질 것 같다.

## 느낀 점

- Next.js는 아직 실무에서 사용해 본 적이 없다. 우선 React에 대한 기본기와 실무적인 활용을 익힌 뒤, 다음 단계로 Next.js를 다뤄봐야겠다.

- AI가 DevTools까지 활용해 프로젝트를 확인할 수 있다는 내용을 보고, GitHub에 올려둔 포트폴리오를 Codex에게 직접 점검해달라고 요청해봤다. Codex Browser와 Developer mode를 사용해 확인해봤는데, 실제 사용자 입장에서 고쳐야 할 부분과 UI·UX 중심의 개선안을 주로 제안해줬다. 사이드 프로젝트가 완성되면 Playwright와 Chrome DevTools MCP를 직접 설치해서 **브라우저 테스트 → 오류 확인 → 코드 수정 → 재검증** 테스트를 해보고싶다.

- GitHub가 스타일링 방식을 CSS Modules 중심으로 전환했다는 내용도 흥미로웠다. 최근 프로젝트에서 Tailwind CSS를 적극적으로 사용하고 있는데, 런타임 비용을 줄이고 CSS를 활용하는 방향과 어느 정도 맞닿아 있다고 생각한다. 

## 정리

- 프레임워크 의존성 버전과 공식 보안 공지를 주기적으로 확인한다.
- 스타일링 방식은 개발 편의성뿐 아니라 런타임 비용과 유지보수 비용도 함께 고려한다.
- AI Agent는 구현뿐 아니라 브라우저 기반 검증과 수정 과정에도 활용할 수 있다.
- AI가 프로젝트를 잘 이해하도록 Context와 작업 규칙을 제공하는 일이 중요하다.
