# 포트폴리오 브라우저 점검 및 개선 기록


## 1. 점검 환경과 항목

배포된 포트폴리오를 Codex Browser와 Developer mode로 탐색요청했다.

[브라우저 사이즈]
- Desktop: `1440px`
- Tablet: `768px`
- Mobile: `390px`

[확인 한 항목]
- 반응형 화면의 레이아웃 깨짐, 가로 스크롤, 콘텐츠 잘림
- 텍스트 가독성, 여백, 정렬, 섹션 간 흐름
- 버튼, 링크, 프로젝트 상세 팝업 인터랙션
- hover, focus, active 상태
- 이미지 비율과 로딩 방식
- Console 오류·경고와 Network 실패 요청
- 키보드와 스크린리더 관점의 기본 접근성
- 첫 화면 로딩과 전체적인 체감 성능
- 키보드 `Tab` 이동과 팝업 열기·닫기
- Projects와 Project Detail 팝업 집중 점검

점검 당시 가로 스크롤, 깨진 이미지, Console 오류·경고, 눈에 띄는 Network 실패 요청은 발견되지 않았다. 프로젝트 상세 팝업과 닫기 기능, 모바일 메뉴, 상단 이동 버튼, 연락처 링크도 정상 동작했다.

## 2. 초기 인트로 대기 시간 단축

### 문제

모바일에서 진입 후 약 `1.2초`가 지나도 인트로 로고만 보였고, 실제 본문은 약 `3.7초` 뒤에 나타났다. 포트폴리오를 처음 확인하는 사용자가 핵심 콘텐츠를 보기 전에 긴 대기 시간을 경험할 수 있는 상태였다.

### 원인

로고 등장, 크기 보정, 원형 텍스트 순차 노출, 대기, 전체 퇴장이 하나의 GSAP 타임라인에서 순서대로 실행되고 있었다. 각 모션은 짧았지만 순차 실행 시간과 `delay`가 합쳐져 전체 대기 시간이 길어졌다.

### 개선

- 로고 등장 시간: `0.4초 → 0.28초`
- 로고 보정 모션: `0.15초 → 0.1초`
- 원형 텍스트 stagger: `0.018초 → 0.01초`
- 마지막 대기: `0.35초 → 0.15초`
- 퇴장 시간: `0.35초 → 0.25초`
- `prefers-reduced-motion` 환경의 인트로도 함께 단축

인트로의 로고와 원형 텍스트 모션은 유지하면서 전체 노출 시간을 약 `1초`대로 줄였다.

**우선순위: 높음**

## 3. 프로젝트 이미지 초기 로딩 개선

### 문제

프로젝트와 팝업에서 사용하는 이미지에 별도의 지연 로딩 설정이 없었고, 일부 원본 이미지는 표시 크기에 비해 해상도와 용량이 큰 상태였다. 현재 화면에 보이지 않는 하단 프로젝트 이미지까지 일찍 요청하면 모바일 네트워크와 이미지 디코딩 비용이 커질 수 있다.

### 개선

화면 아래에 위치한 프로젝트 이미지에 `loading="lazy"`와 `decoding="async"`를 적용했다. Project Detail과 Side Project 이미지는 팝업이 열릴 때만 DOM에 생성되는 기존 구조를 유지했다.

```tsx
<img
  src={project.image}
  alt={`${project.title} 화면`}
  loading="lazy"
  decoding="async"
/>
```

현재 화면에 필요하지 않은 프로젝트 이미지는 뷰포트에 가까워졌을 때 로딩되고, 이미지 디코딩이 메인 렌더링을 과도하게 막지 않도록 개선했다. 이미지의 WebP·AVIF 변환과 원본 리사이즈는 시각 품질 검증이 필요한 별도 작업으로 남겨두었다.

**우선순위: 높음**

## 4. 키보드 포커스 표시 보강

### 문제

실제 브라우저에서 `Tab` 키로 상단 메뉴를 이동했을 때 일부 링크와 버튼에서 현재 포커스 위치를 빠르게 알아보기 어려웠다. 키보드 사용자는 포커스 위치를 기준으로 페이지를 탐색하기 때문에 현재 선택된 요소를 알기 어려우면 다음 동작을 예측하기 힘들다.

### 개선

마우스 클릭에는 영향을 주지 않고 키보드 탐색에서만 보이는 `:focus-visible` 스타일을 전역으로 추가했다. 기존 디자인 토큰인 `--primary`를 사용해 포트폴리오의 시각적 톤도 유지했다.

```css
:where(a, button, input, select, textarea, [role="button"], [tabindex]):focus-visible {
  outline: 0.3rem solid var(--primary);
  outline-offset: 0.3rem;
}
```

키보드로 링크와 버튼을 이동할 때 현재 위치가 연보라색 outline으로 명확하게 표시된다.

**우선순위: 높음**

## 5. Projects 카드와 상세 팝업의 접근성 의미 보강

### 문제

프로젝트 카드의 시각적 정보는 충분했지만, 카드·제목·설명의 관계와 DETAIL 버튼이 팝업을 연다는 의미가 접근성 트리에 충분히 전달되지 않았다. 팝업을 열고 닫을 때 포커스 이동도 보강할 필요가 있었다.

### 개선

- 프로젝트 카드의 최상위 요소를 `div`에서 `article`로 변경
- 카드와 제목을 `aria-labelledby`로 연결
- 카드와 설명을 `aria-describedby`로 연결
- DETAIL 버튼에 프로젝트명이 포함된 `aria-label` 추가
- DETAIL 버튼에 `aria-haspopup="dialog"` 추가
- 상세 팝업의 제목과 개요를 `aria-labelledby`, `aria-describedby`로 연결
- 팝업을 열면 닫기 버튼으로 포커스 이동
- 팝업을 닫으면 기존 DETAIL 버튼으로 포커스 복원
- 기존 `role="dialog"`, `aria-modal="true"`, ESC 닫기, 배경 스크롤 잠금 유지

프로젝트 카드와 상세 팝업의 관계가 보조 기술에 더 명확히 전달되고, 키보드 사용자가 팝업을 닫은 뒤 기존 탐색 위치에서 자연스럽게 이어갈 수 있게 되었다.

**우선순위: 중간**

## 6. Side Projects 문구 오타 수정

소개 문구의 `개인 프론트엔으 작업물입니다.`를 `개인 프론트엔드 작업물입니다.`로 수정했다. 작은 오타도 콘텐츠 검수와 작업 완성도에 대한 신뢰에 영향을 줄 수 있기 때문이다.

**우선순위: 낮음**

## 7. 검증

### 브라우저 검증

- Codex Browser에서 로컬 프로젝트를 직접 실행하고 화면 표시 확인
- 데스크톱·태블릿·모바일 기준 레이아웃 확인
- 프로젝트 DETAIL 버튼과 상세 팝업 열기·닫기 확인
- 키보드 포커스 표시와 팝업 포커스 복원 흐름 확인
- Side Projects 수정 문구 확인

### Developer mode 검증

- Console 오류·경고 없음
- 화면상 깨진 리소스와 확인 가능한 Network 실패 요청 없음
- 개별 리소스의 실제 전송 용량은 production build 결과와 함께 확인

### 정적 검사

```bash
npm run lint
npm run build
```

- ESLint 통과
- TypeScript 검사 통과
- Vite production build 통과
- `git diff --check` 통과

## 정리

- 실제 브라우저 탐색으로 코드만으로 놓치기 쉬운 로딩, 포커스, 팝업 흐름을 점검했다.
- 인트로 대기 시간을 줄이고, 프로젝트 이미지의 초기 로딩 비용을 낮췄다.
- `:focus-visible`과 팝업 포커스 복원으로 키보드 접근성을 보강했다.
- Projects 카드와 팝업의 의미를 보조 기술에 더 명확히 전달하도록 개선했다.
